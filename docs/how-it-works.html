AI Act Check

An API that AI agents pay 60 cents to ask one question: where does this AI use case sit under the EU AI Act, and what do I have to do?

Say it in 30 seconds

Every team shipping AI in Europe asks the same thing: is this allowed, is it high-risk, or is it fine? Today the answer is a consultant and a week. But agents write the code now. So the agent asks at the moment it matters. It reads our free questionnaire, fills it in, and calls the check. The API says "that's 60 cents", the agent pays over Stripe's machine payments, and gets the verdict: the risk tier, the articles, its duties and the dates. Rule-based, cited, nothing stored. Not legal advice; a first pass for less than a coffee.

402The web's "Payment Required" status. The API answers it with a price instead of the result.
MPPStripe's Machine Payments Protocol: a standard way for a program to pay a 402 and retry, no human in the loop.
Test cardStripe's sandbox test Visa. The agent pays with it through a Shared Payment Token, and each payment shows in the Stripe dashboard. No real money moves.
ReceiptProof of payment the API sends back with the verdict. We log its id, never the use case.

The flow

One paid check, start to finish

  1. Diego types a use case in the console box (or picks a preset) and presses Run.
  2. The agent (Claude Code, running headless) asks the API for the questions. GET /questions is free.
  3. The agent turns the use case into answers: role, data, purpose. 33 short questions, most of them yes or no.
  4. It sends the answers to POST /classify. Bad answers are rejected here, before any price.
  5. The API answers 402: "pay 0.60 USD".
  6. The agent pays with Stripe's test card over MPP, via the mppx tool. The payment lands in the Stripe dashboard.
  7. The agent sends the same request again, now with proof of payment.
  8. The rules engine decides: Hank's 34 rules in data/rules.json. No LLM, same answers give the same verdict.
  9. The verdict comes back with the receipt: tier, articles, duties for the role, dates, the disclaimer.
  10. It lands on the live screen, localhost:4242/live, on the projector.
  11. The agent saves a record in its own project: compliance/ai-act-*.md.

Questions people will ask

Short answers

Why pay per call?

The agent needs the answer once, at the moment it writes the code. No account, no subscription, no human signing up. 60 cents, paid by the agent itself.

Why no LLM in the verdict?

So what you pay for is checkable. Same answers, same verdict, every time, and every line cites its article. The agent does the reading; the rules do the deciding.

What do you store?

Nothing about the use case or the answers. The receipts log holds the time, the tier, the amount and the receipt id. That's it.

Is it real money?

No. Stripe's test card in a sandbox. The payment is a real Stripe payment in test mode, so it shows in the dashboard. The flow is the real one.

Why 60 cents, not 50?

Stripe's minimum card charge in euros is €0.50, and 50 US cents is about €0.45. MPP also supports stablecoins on Tempo, which the console can switch to.

What is MPP?

Stripe's Machine Payments Protocol. The server answers 402 with a price, the client pays and retries with proof. Payments built into plain HTTP.

Is this legal advice?

No. Every verdict carries the disclaimer. It's a first pass; anything using the Art. 6(3) exception or police biometrics needs a lawyer.

What's next?

The same check as a paid MCP tool, so Claude or ChatGPT pay inside the chat. Then Chile's new data law, Ley 21.719.
